# Yuque Sync

一个用于在 Obsidian 与语雀之间同步 Markdown 文档的插件。

- 最低支持版本：Obsidian 1.4.4
- 文档同步使用语雀 API v2
- 图片上传依赖语雀网页端 Cookie 和非公开上传接口

## 功能

- **上传当前文档**：根据 YAML 前置元数据中的 `yuque_link` 更新语雀文档
- **创建语雀文档**：当当前文件没有 `yuque_link` 时，使用 Token 自动选择或创建私密知识库，并自动写回链接
- **增量同步检测**：为万级笔记库维护本地同步索引，日常只真正处理新增、修改、重命名、失败或远端状态到期的文档
- **完整同步检测**：需要时可以强制重新读取并校验全部文档，支持暂停和断点继续
- **同步方向判断**：通过最近同步正文 SHA-256 基线区分已同步、本地已修改、语雀已修改、冲突和尚未建立基线的内容不同
- **批量推送未关联文档**：将没有 `yuque_link` 的 Markdown 文档串行创建到自动管理的知识库池，并写回链接
- **批量推送失败保护**：某篇文档真正推送失败时立即停止后续任务，并显示失败文件、原始错误、已完成数量与剩余未执行数量
- **下载语雀文档**：比较两端修改时间，确认后覆盖本地正文，并先创建集中备份
- **上传本地图片**：支持单张图片和当前文档全部图片，兼容 Markdown 图片与 Obsidian Wiki 图片引用
- **并发与限流保护**：同步检测使用有限并发，并对 429 和 5xx 请求进行指数退避重试
- **创建恢复保护**：语雀文档创建成功但本地 `yuque_link` 写回失败时，会记录待恢复状态，避免下次批量操作重复创建文档

## 配置

在 Obsidian 的“设置 → 第三方插件 → Yuque Sync”中配置：

- `Yuque Token`：用于读取、创建和更新语雀文档，也用于自动识别账号并创建同步知识库
- `Yuque Cookie`：仅用于图片上传
- `远端元数据重新检查周期`：本地没有变化时，多久重新确认一次语雀远端状态；默认 24 小时
- `远端降级校验预算`：当远端批量元数据不可用或尚未建立远端基线时，每次增量检测最多逐篇请求多少篇正文；默认 200
- `同步检测并发数`：默认 4，可在 1～8 之间选择

> Token、Cookie、创建恢复状态、同步索引、脏文件队列和未完成扫描进度会保存在当前 Obsidian 仓库的插件数据目录中。不要提交或分享插件的 `data.json`。
>
> 图片上传依赖语雀网页端的非公开接口和 Cookie，可能随语雀接口调整而失效；文档同步使用语雀 API v2。

## 文档元数据

已关联语雀文档的本地文件需要包含：

```yaml
---
yuque_link: https://www.yuque.com/your_namespace/your_book/document-slug
---
```

插件还会维护以下字段：

- `yuque_title`：语雀文档标题
- `yuque_updated_at`：最近一次下载或恢复关联时语雀返回的更新时间

如果某个 Markdown 文档不应参与语雀批量扫描和批量推送，可以设置：

```yaml
---
yuque_sync: false
---
```

设置后，手动上传当前文档也会被阻止，防止误同步。

## 使用方法

### 上传到语雀

点击左侧上传图标，或在命令面板执行“Yuque Sync: 上传当前文档到语雀”。

- 已存在 `yuque_link`：覆盖对应语雀文档
- 不存在 `yuque_link`：自动选择/创建有容量的私密知识库，并将链接写回 YAML

成功上传、创建、恢复关联或从语雀下载后，插件会同步刷新本地索引和最近同步正文 Hash。

如果远端文档已经创建，但插件在写回本地 `yuque_link` 前中断，下一次创建时会优先尝试恢复已有远端文档关联，而不是直接再次创建。

## 自动知识库分片

从 1.3.3 开始，新建语雀文档不再要求用户配置 `namespace/book`。插件只需要 `Yuque Token`：

1. 通过语雀 OpenAPI `/user` 自动识别 Token 所属账号；
2. 查找带有 Yuque Sync 专用标记的托管知识库；
3. 首次没有托管库时自动创建私密的 `Obsidian Sync 001`；
4. 插件侧采用 4800 篇软上限，接近容量后自动创建 `Obsidian Sync 002`、`003`……；
5. 已有 `yuque_link` 的旧文档继续同步原知识库，不迁移；
6. 插件只自动管理自己创建并带专用描述标记的知识库，不会把用户其他知识库加入分片池。

知识库文档数会缓存在插件设置中，并在首次发现、缓存过期、接近软上限或创建文档疑似因容量失败时重新通过 OpenAPI 校验。批量推送会串行使用同一知识库池，因此跨过单库容量阈值时可以无人工干预地继续到下一库。

> 4800 是插件为了给语雀端手工创建、缓存误差和并发留余量而采用的安全软上限，不声明为语雀官方硬限制。

## 设置页同步控制中心

同步状态不再通过单独弹窗展示。插件设置页现在直接提供增量检测、完整检测、暂停检测、批量推送未关联文档、状态概览、搜索筛选和文档列表。同步索引会持久化，重启 Obsidian 后仍可在设置页查看当前状态；最近一次扫描摘要也会保留。

## 语雀 OpenAPI 主动限流

从 1.3.1 开始，插件不会只依赖并发数和 HTTP 429 被动退避，而是在所有语雀 OpenAPI 文档/目录请求前经过同一个全局请求队列。

限流器同时检查最近 1 秒、1 分钟和 1 小时三个滑动窗口。默认采用插件侧保守值：

- 每秒最多 2 次
- 每分钟最多 50 次
- 每小时最多 4000 次

这些值是为了给其他客户端和突发操作预留空间的**插件保守默认值**，不声明为语雀官方硬上限。语雀调整 OpenAPI 配额后，可以在插件设置中直接修改三个窗口，无需改代码。秒/分钟/小时的当前硬限制请以语雀 OpenAPI 官方页面为准。

请求优先级为：手动上传/下载 > 文档创建与目录操作 > 后台增量/完整检测。后台扫描即使有多个 worker，也不会绕过全局限流器。

如果语雀返回 HTTP 429：

1. 优先读取 `Retry-After`
2. 暂停整个 OpenAPI 请求队列，而不是只暂停当前 worker
3. `Retry-After` 不可用时默认暂停 60 秒
4. 429 最多自动重试 3 次
5. 最近一小时请求历史和暂停截止时间会持久化，重启 Obsidian 不会立刻把小时计数清零

> 图片上传使用语雀网页 Cookie 的非公开上传接口，不计入这里的 OpenAPI 请求队列。

## 大规模笔记库同步检测

针对一万到数万篇 Markdown，插件不再把每次检测都当成“读取全部文件并逐篇请求语雀”。

### 增量检测（默认推荐）

在命令面板执行：

```text
Yuque Sync: 增量检测文档同步状态
```

插件会维护持久化 `SyncIndex`，记录每篇文档的：

- 路径、文件大小和修改时间
- `yuque_link`
- 本地正文 Hash
- 最近读取到的远端正文 Hash
- 最近同步正文 Hash
- 语雀 `updated_at`
- 最近远端检查时间
- 最近同步状态

插件在 Obsidian 布局加载完成后监听 Markdown 的 `create`、`modify`、`rename`、`delete` 事件，把真正变化的文档加入脏文件队列。

下一次增量检测时：

1. 先遍历 `TFile.stat`，通过 `mtime + size` 和脏文件队列筛选候选文档
2. 没有变化且远端检查未过期的文档直接复用索引，不读取正文
3. 需要读取正文时使用 `vault.cachedRead()`，避免不必要的重复磁盘读取
4. 本地正文使用 SHA-256 保存同步基线
5. 对已建立远端 `updated_at` 的文档，优先按知识库批量读取远端文档元数据
6. 如果远端 `updated_at` 没变，则不下载正文
7. 只有远端更新时间改变、本地发生变化或需要建立基线的文档才进入正文请求队列
8. 如果远端批量元数据接口不可用，则按照“远端降级校验预算”逐步验证，不会一次发起上万次请求

### 首次建立索引

第一次在已有大型 Vault 中执行增量检测时，插件会读取本地 Markdown 并建立索引，但**不会立即为所有已关联文档逐篇下载语雀正文**。

尚未完成远端正文验证的文档会显示：

```text
待远端校验
```

后续增量检测会按照远端元数据和降级预算逐步完成验证。如果需要立刻对全部已关联文档做深度校验，可以手动执行完整检测。

### 完整检测

在命令面板执行：

```text
Yuque Sync: 完整检测所有文档同步状态
```

完整检测会强制深度校验所有非忽略 Markdown，并可能为全部已关联文档下载语雀正文。因此在 15,000+ 笔记库中耗时和 API 请求量都会明显高于增量检测。

开始前插件会再次确认。扫描过程中会定期保存进度；可以执行：

```text
Yuque Sync: 暂停当前同步检测
```

暂停后会保留未处理路径。下一次执行同一种检测模式时，会从保存的扫描会话继续处理，而不是从第一篇重新开始。

### 同步状态

状态面板会区分：

- `已同步`：两端正文 Hash 相同，同时刷新最近同步基线
- `本地已修改`：本地 Hash 相对最近同步基线发生变化，远端仍是基线版本
- `语雀已修改`：远端 Hash 相对最近同步基线发生变化，本地仍是基线版本
- `冲突`：本地和语雀都相对最近同步基线发生变化
- `内容不同`：两端内容不同，但还没有可靠的最近同步基线
- `待远端校验`：本地索引已经建立，但远端正文尚未完成验证
- `未关联`：没有 `yuque_link`
- `链接异常`：`yuque_link` 无法解析为有效语雀文档地址
- `远端不存在`：语雀返回 404
- `YAML 异常`：Frontmatter 无法解析
- `检测失败`：网络、权限或其他 API 错误
- `已忽略`：设置了 `yuque_sync: false`

如果用户手动把 `yuque_link` 修改为另一篇语雀文档，插件会丢弃旧链接对应的同步基线，避免把另一篇文档错误判定成冲突。

### 大量结果的界面保护

同步状态统计始终覆盖全部文档，但表格最多渲染优先级最高的 500 条结果，优先显示冲突、修改、异常和未关联文档。

这样可以避免 15,000+ 行 DOM 同时渲染导致 Obsidian 在“检测已经完成”后反而出现界面卡顿。

### 批量推送未关联文档

在命令面板执行“Yuque Sync: 批量推送未关联文档到语雀”，或从同步状态面板点击“推送未关联文档”。

插件会：

1. 重新扫描所有未关联 Markdown 文档
2. 自动跳过备份文件和 `yuque_sync: false` 文档
3. 显示本次预计创建数量并只确认一次
4. 串行创建语雀文档，避免一次性高并发请求
5. 为成功创建的文档写回 `yuque_link` 和 `yuque_title`
6. 尝试加入语雀知识库目录
7. 为成功创建的文档立即建立同步 Hash 基线
8. 单篇失败时继续处理后续文档，并在最后汇总结果

### 从语雀下载

点击左侧下载图标，或在命令面板执行“Yuque Sync: 从语雀下载当前文档”。

插件会先显示本地和语雀修改时间。确认覆盖后，会先备份原文，再覆盖当前文件，并刷新同步 Hash 基线。

#### 备份机制

备份统一放在：

```text
.yuque-sync/backups/
```

插件会保留原目录结构。例如：

```text
原文件：
Notes/Programming/TypeScript.md

备份：
.yuque-sync/backups/Notes/Programming/TypeScript.backup-20260810-213000.md
```

这样可以避免备份文件混入普通笔记目录，也不会被批量同步扫描和批量推送识别为待创建文档。

旧版本创建的：

```text
文件名.backup-YYYYMMDD-HHMMSS.md
```

也会被新的批量扫描逻辑自动忽略。

### 上传图片

- 在编辑器中右键本地图片引用，选择“上传图片到语雀”
- 在 Markdown 文件上右键，选择“上传文档中的所有图片到语雀”
- 或通过命令面板执行批量上传

批量上传期间如果文档内容发生变化，插件不会自动覆盖文件，防止丢失新的编辑。

## 安装

### 通过 BRAT

1. 安装 [BRAT](https://obsidian.md/plugins?id=obsidian42-brat)
2. 添加仓库 `weepwood/yuque-sync`
3. 启用插件

### 手动安装

从 Releases 下载最新版，将以下文件放入 Obsidian 插件目录的 `yuque-sync` 文件夹：

- `main.js`
- `manifest.json`
- `styles.css`

## 开发

开发环境建议使用 Node.js 22 或更高版本；GitHub Actions 使用 Node.js 24。

```bash
npm ci
npm run dev
npm run lint
npm run typecheck
npm run build
npm run check
```

- `npm run lint`：使用 ESLint 9 和 Obsidian 官方 `eslint-plugin-obsidianmd` 检查插件开发规范
- `npm run typecheck`：使用 TypeScript 5.x 执行严格类型检查
- `npm run build`：类型检查后使用 esbuild 生成生产版 `main.js`
- `npm run check`：依次执行 lint、typecheck 和生产构建，CI 使用该命令作为主验证入口

项目结构：

```text
main.ts                    插件入口与工作流编排
src/yuque-client.ts        语雀 API、文档元数据列表与图片上传客户端
src/markdown-utils.ts      YAML、链接、同步过滤与图片引用处理
src/sync-engine.ts         增量索引、Hash、远端筛选、并发重试与断点扫描引擎
src/sync-status-modal.ts   大规模同步状态面板
src/settings-tab.ts        插件设置页
src/confirm-modal.ts       确认弹窗
src/types.ts               共享类型
```
